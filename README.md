# 데이터로 의사결정을 돕는 분석가입니다

숫자가 막힌 곳에서 원인을 찾고, 기준선을 세워 "이 숫자가 정말 맞는가"를 증명합니다.

- **지표가 흔들리면 집계 전에 '무엇을 세고 있는지'부터 되짚습니다** — 주문 99,441건이 실제로는 96,096명이 낸 것임을 식별자 교정으로 밝혀, 0%에 가깝게 왜곡되던 리텐션을 바로잡음 → [fintech-cohort-funnel-sql](https://github.com/hwasun-zip/fintech-cohort-funnel-sql)
- **예측이 정체되면 모델 대신 데이터로 돌아갑니다** — 축제 방문객 예측에서 세운 날씨 가설을 검증으로 기각하고, 정확도가 낮았던 원인이 광역 관측소 근사와 월 단위 매칭에 따른 신호 희석임을 밝혀냄 → [festforecast](https://github.com/hwasun-zip/festforecast)
- **분석은 실행 가능한 답으로 끝냅니다** — SQL 기반 RFM 세그먼트로 핵심 고객 23.4%가 매출 67.6%를 만든다는 구조를 특정하고, 세그먼트별 액션까지 제안 → [rfm-customer-segmentation](https://github.com/hwasun-zip/rfm-customer-segmentation)
- **개선은 지표의 전후 비교로 증명합니다** — 날씨 기반 음식 추천에서 무작위 대비 Hit@1 3배(58.8%)를 시점 분할 검증으로 확인 → [yamyam](https://github.com/hwasun-zip/yamyam)
- **결과가 비현실적으로 좋으면 이상치부터 의심합니다** — 클러스터링 실루엣 0.98이 이상치가 만든 '가짜 분리'임을 발견해 교정 → [health-bab-talk](https://github.com/hwasun-zip/health-bab-talk)
